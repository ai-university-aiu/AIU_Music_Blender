1. THE STORY SO FAR
--------------------------------------------------------------------------------
This project began with a simple question: "Where did the Infinite Jukebox go?"

The Infinite Jukebox (originally on Echo Nest Labs) took a song, chopped it up
on the beat, built a graph of beats that sound alike, and then played the song
FOREVER by randomly jumping between similar beats. It died when Echo Nest Labs
went away. It was resurrected as The Eternal Jukebox, which itself broke in
mid-2023 when Spotify changed its API, and was revived again at eternalbox.dev.

Then we actually went and tested the survivors (2026-08-07):

  * infiniby.com  — the "spiritual successor" that takes YouTube links.
    Frontend loads, but POST /api/analyze returns 404 "Application not found".
    The analysis backend has been undeployed. Every song fails.

  * eternalbox.dev — Cloudflare 522, origin server not responding. Whole site
    down. Retried; same result.

Every hosted incarnation of this beloved idea is currently dead or broken, and
every death traces back to the same root cause: DEPENDENCE ON SOMEONE ELSE'S
SERVER OR API (Echo Nest, then Spotify, then somebody's abandoned backend).

Conclusion: we clone it, we own it, and we make the analysis pipeline OURS so
it can never die on us again. And while we're in there, we make it smarter.

--------------------------------------------------------------------------------
2. WHAT WE ARE CLONING AND WHY
--------------------------------------------------------------------------------
Root clone repo (the ancestor we build on):

    https://github.com/EternalBox/EternalJukebox

This is the open-source rehosting of the Infinite Jukebox. It contains the
complete working core: beat-graph construction, the iconic arc-diagram
visualization, and the infinite random-walk player. That core logic is proven
and beloved — we do NOT rewrite it, we adopt it and extend around it.

GOLDEN RULE: the original Infinite Jukebox functionality must keep working,
unmodified in behavior, at every stage of this project. All new features are
additive — new modules, new entry points, new modes — never edits that change
what the classic mode does.

Create our repo (one line, run on ccai2):

    gh repo create AIU_Music_Blender --description "Artificial Intelligence (AI) Music Blender" --public --clone

(Use --private instead of --public if preferred. Then vendor/fork the
EternalJukebox source into it, preserving its license and attribution.)

3. THE BIG FIX: SELF-HOSTED AI ANALYSIS PIPELINE
--------------------------------------------------------------------------------
The project's historical fatal flaw was the Spotify/Echo Nest analysis API.
We replace it entirely with our own local ML pipeline:

  * Beat & downbeat tracking........... librosa / madmom
  * Timbre & pitch features............ MFCCs + chroma per beat
  * Key & tempo estimation............. chroma-based key detection
  * Section / structure detection...... self-similarity segmentation
  * (Later) stem separation............ Demucs — vocals / drums / bass / other

Input: any audio file, or a YouTube link (downloaded locally, analyzed
locally). No external analysis API. Nothing to deprecate. Nothing to die.

This is Resume Attack #1: "Replaced a deprecated commercial audio-analysis API
with a self-hosted ML pipeline." A genuinely strong full-stack ML story.

--------------------------------------------------------------------------------
4. THE AI RESUME PROJECT ATTACK (planned AI upgrades)
--------------------------------------------------------------------------------
Beyond the pipeline replacement, in rough order of ambition:

  a) LEARNED BEAT EMBEDDINGS — replace hand-tuned beat-similarity distance
     with a small contrastive/triplet model trained so "sounds seamless to a
     human ear" is the learned metric. Adjacent beats give free positive
     training pairs. Baseline vs. learned metric, with listenable A/B results.

  b) RL / MDP WALK POLICY — frame infinite playback as a Markov decision
     process: reward smooth transitions, penalize repetition and stuck loops.
     Classic algorithm -> learned policy narrative.

  c) NATURAL-LANGUAGE STEERING — "keep it mellow", "build to the drop and
     stay there" -> an LLM maps requests to walk parameters (energy bias,
     section weights). Cheap to build, fantastic demo.

  d) GENERATIVE PATCHING (stretch goal) — where no good jump exists,
     synthesize a short transition with a small neural audio model so any two
     sections become connectable.

Fun extras on the list: chaos slider (jump probability), chorus gravity,
shareable deterministic walk seeds, upgraded visualizations (force-directed /
WebGL alongside the classic arc diagram — never replacing it).

5. THE_AI_MASHUP_MACHINE — MASH-UP MODE
--------------------------------------------------------------------------------
A new, additive mode: take TWO songs and create a mash-up.

The three hard problems and our answers:
  1) TEMPO — time-stretch without pitch shift (rubberband / phase vocoder);
     keep stretches under ~8% by preferring compatible pairs.
  2) KEY/HARMONY — chroma-based key detection + Camelot-wheel harmonic
     compatibility scoring; pitch-shift +/- 1-2 semitones for near-matches.
  3) FREQUENCY COLLISION — Demucs stem separation, then mash STEMS:
     vocals from Song A over the instrumental of Song B, with EQ ducking.

Pipeline sketch:

  Song A -> beats/downbeats -> key+chroma -> stems -+
                                                    +-> compatibility scorer
  Song B -> beats/downbeats -> key+chroma -> stems -+        |
                                                     alignment engine
                                                (downbeats & 8/16-bar phrases)
                                                             |
                                                       mix renderer

And the crown jewel: mash-ups that PLAY IN THE AI-MUSIC-BLENDER — the rendered
mash-up (or the paired beat-graph of both songs) feeds back into the infinite
jukebox engine, so a two-song mash-up can play forever, drifting between both
songs through harmonically compatible sections. Infinite mash-up radio.

Compatibility scoring is Resume Attack #2: train a "mashability" model — the
genuinely novel research-flavored piece of this project.

Legal note: runs on the user's own files / local downloads, renders locally,
nothing hosted or distributed. Keep it that way.

6. THREE WAYS TO RUN IT
--------------------------------------------------------------------------------
  1. COMMAND LINE
       aiu-music-blender jukebox  File1                 # classic infinite mode
       aiu-music-blender mashup   File1 File2           # The_AI_Mashup_Machine
       aiu-music-blender jukebox  <YouTube-URL>         # fetch + analyze + play
     (File1 for Infinite Jukebox; File1 + File2 for The_AI_Mashup_Machine.)

  2. WEB PAGE INTERFACE — localhost for now. The EternalJukebox already ships
     a web UI; we extend it with the mash-up mode and local-pipeline backend.
     No public hosting, no accounts, no API keys.

  3. UBUNTU GUI APP — our first native Ubuntu desktop app! Target: Ubuntu
     Studio 24.04 (ccai2's OS — fitting, since Ubuntu Studio is the audio
     production flavor). Recommended stack: GTK4 + libadwaita via PyGObject
     (Python, same language as the ML pipeline; native GNOME look; GStreamer
     for audio playback; and Ubuntu Studio ships the low-latency audio stack).
     Alternative if we want the arc-diagram canvas for free: wrap the web UI
     in a WebKitGTK window. Decide at build time; the CLI and web UI come
     first so the GUI is a thin shell over a working engine.

  INPUTS (all modes): local audio files or YouTube links.
       Infinite Jukebox mode........ File1
       The_AI_Mashup_Machine........ File1 + File2
